# Release preparation

Build from the repository root with `python3 tools/build_release.py --output /private/output/path`. The native archive includes the CLI binary, Python server and migrations, pinned dependency list, lifecycle controller, plugin, skill and instructions. The clean installer requires Python and PostgreSQL tools; source builds also require Go. Dependencies may be fetched from the package index, so this is not an offline installer.

Install into a fresh `REMOTE_AGENT_SESSION_INSTALL_DIR` using `sh install/install.sh`. Verify start, repeated start, status, stop, restart and cleanup in a private temporary service directory separate from client state, using `--service-state-dir` / `REMOTE_AGENT_SESSION_SERVICE_STATE_DIR`; client `--state-dir` remains independent. Then verify both native hosts and a separate Feishu application. Never use a real application's credentials in offline tests or share an event consumer with an existing deployment.

Run Python, Go and plugin tests before creating the candidate. Check checksum, distribution contents, secret scanning, license ownership and included third-party notices before publishing. The extracted project is authorized for publication under MIT. Include the root LICENSE and third-party notices in every distribution.

The dependency lock is regenerated from `server/uv.lock` with `uv export --project server --no-dev --no-emit-project --format requirements-txt --output-file install/requirements.lock`. Refresh third-party license metadata whenever dependencies change. Do not publish a candidate whose license notices or versioned resources are incomplete.

## Native Windows candidate

Build on a native Windows runner with `python tools/build_release.py --output C:\private\release-output`. Cross-OS `GOOS` values are rejected: a Windows label must contain a native `.exe`. The Windows output is a ZIP and SHA-256 sidecar containing `bin/remote-agent-session.exe`, the pinned requirements, backend/migrations, PowerShell install/uninstall scripts and the packaged DSH plugin asset. Including the asset preserves a complete release; it does not enable DSH on Windows. Unix builds continue to emit `.tar.gz` archives. Do not set a cross-architecture `GOARCH` when producing a native release.

Extract into a temporary directory and run `.\install\install.ps1` in non-elevated PowerShell with Python 3.11+ and PostgreSQL 15+ tools. Go is needed only for source installation, not the archive's prebuilt CLI. Verify `.venv\Scripts\python.exe`, private inherited ACLs, the ownership marker, refusal of existing destinations and the executable's installed lifecycle dispatch. Check offline start, duplicate start, status, doctor, stop, restart and owned uninstall with real PostgreSQL persistence and an isolated client/service root. Uninstall must retain private state and preserve a replacement installation's supervisor. No global PATH, shell-profile or Windows service setup is permitted.

Windows CI runs native Go builds/tests and backend/lifecycle checks. Read its exact workflow to distinguish native persistence checks and boundary substitutes from real-host acceptance. Release acceptance additionally requires the explicit shared foreground Codex CLI workflow, exact session identity, local/remote origin isolation, answer/question/approval round trips, interrupt/reconnect and actual Feishu phone receipt. Neither CI nor archive creation proves those manual outcomes.
